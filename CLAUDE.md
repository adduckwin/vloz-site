# CLAUDE.md — инструкция для Claude Code

Это статический сайт студии **VLOZ** (Антон Кряквин, сезонные/авторские меню
для кофеен). Домен **duckwin.ru**. Твоя задача — залить репозиторий на GitHub
и задеплоить сайт на хостинг.

## ⚠️ Прежде чем что-то делать

1. **Не коммить секреты.** Пароли, токены, ключи, данные FTP/SSH — никогда не
   попадают в git и не пишутся в файлы репозитория. Используй переменные
   окружения или спрашивай у пользователя в момент выполнения.
2. **Ничего не удаляй на хостинге** без явного подтверждения пользователя.
3. Если каких-то доступов или данных не хватает — **спроси пользователя**,
   не угадывай.

## Структура репозитория

```
build.py            одна команда пересборки: python3 build.py
build/              движок (patch.py → лендинг, blog_build.py → блог, deploy_build.py → dist/)
assets/             исходные картинки + robots.txt (на хостинг НЕ идут)
dist/               ГОТОВЫЙ САЙТ — заливается в корень хостинга
.build/             промежуточные файлы (в .gitignore, можно игнорировать)
```

Деплоить нужно **содержимое `dist/`** так, чтобы `dist/index.html` открывался
по `https://duckwin.ru/`. Чистые URL (`/blog/`, `/blog/название/`) требуют, чтобы
сервер отдавал `index.html` из папки — на nginx/Apache/shared-хостинге это так по умолчанию.

## Шаг 0. Пересборка (только если меняли тексты/картинки)

Нужен Python 3 и Pillow. Если правок не было — пропусти, `dist/` уже актуален.
```bash
pip install pillow        # если не стоит
python3 build.py          # обновит dist/
```
Проверь, что сборка прошла без ошибок и в `dist/` есть `index.html`, `blog/`, `img/`.

## Шаг 1. Залить на GitHub

Спроси у пользователя URL репозитория (или предложи создать). Репозиторий уже
инициализирован, первый коммит есть (`git log` покажет).

Если установлен `gh` и пользователь авторизован (`gh auth status`):
```bash
gh repo create vloz-site --private --source=. --remote=origin --push
```

Иначе вручную (пользователь сам создаёт пустой репозиторий на github.com БЕЗ
README и .gitignore, даёт тебе URL):
```bash
git branch -M main
git remote add origin <URL_РЕПОЗИТОРИЯ>   # https://github.com/ЛОГИН/vloz-site.git
git push -u origin main
```
Если просит логин/пароль по HTTPS — нужен Personal Access Token вместо пароля
(пользователь создаёт его сам в Settings → Developer settings). Не вписывай токен
в команды/файлы — пусть git спросит интерактивно или используется gh/SSH.

## Шаг 2. Задеплоить dist/ на хостинг

**Сначала спроси у пользователя тип хостинга и способ доступа**, затем выбери рецепт.
Заливается именно содержимое `dist/` (а не сам каталог `dist`).

### Вариант A — shared-хостинг по SSH (Beget, Timeweb и т. п.)
Узнай у пользователя: host, SSH-логин, путь к корню сайта (часто
`~/duckwin.ru/public_html`, `~/public_html` или `/var/www/duckwin.ru`).
```bash
rsync -avz --delete dist/ ПОЛЬЗОВАТЕЛЬ@ХОСТ:ПУТЬ_К_КОРНЮ/
```
`--delete` синхронизирует точь-в-точь (удалит на сервере то, чего нет в dist).
Если пользователь не хочет удаления — убери флаг и подтверди это с ним.

### Вариант B — только FTP/SFTP
Узнай host, логин, пароль (пароль — НЕ в команду; экспортируй в окружение или
дай lftp спросить). Пример через lftp:
```bash
lftp -u "ЛОГИН" ftp://ХОСТ -e "set ftp:ssl-allow no; mirror -R --delete dist/ /ПУТЬ_К_КОРНЮ; bye"
```
Пароль введи в интерактивном приглашении lftp, не в shell-историю.

### Вариант C — свой VPS с nginx
```bash
rsync -avz --delete dist/ ПОЛЬЗОВАТЕЛЬ@ХОСТ:/var/www/duckwin.ru/
```
Конфиг nginx (если ещё не настроен) — `root /var/www/duckwin.ru;` и
`try_files $uri $uri/ =404;`. SSL — через certbot. Меняй nginx-конфиг и
перезапускай сервис только с подтверждения пользователя.

### Вариант D — панель управления без SSH/FTP
Тогда автоматический деплой невозможен: сообщи пользователю, что нужно вручную
загрузить содержимое `dist/` через файловый менеджер панели в корень сайта.

## Шаг 3. Проверка после деплоя

```bash
curl -sI https://duckwin.ru/ | head -1                 # 200 OK
curl -s https://duckwin.ru/sitemap.xml | head -3       # отдаётся sitemap
curl -sI https://duckwin.ru/blog/ | head -1            # 200 OK (чистый URL блога)
```
Открой в браузере главную и одну статью блога — проверь, что картинки грузятся.

## Что осталось на пользователе (не автоматизируй без него)

1. Метрики в `dist/index.html` (`<head>`): `00000000` → счётчик Яндекс.Метрики,
   `G-XXXXXXXXXX` → Measurement ID Google Analytics. Лучше править в
   `build/template2.html` и пересобрать.
2. Домен + SSL (если ещё не подключены).
3. Добавить сайт в Яндекс.Вебмастер и Google Search Console, скормить
   `https://duckwin.ru/sitemap.xml`. Завести карточку в Яндекс.Бизнес.
